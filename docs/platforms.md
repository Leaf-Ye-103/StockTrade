# Platforms and data sources

For the requested affordable minute-based and forward-paper workflow, start by validating Alpaca historical data against the existing observed-trade evaluator. Massive is an alternative data source. LEAN is an optional research/backtest harness, but its standard equity fill model must be replaced to preserve this project's rule against unsupported executions. Treat venue-specific Databento MBO data and an engine such as NautilusTrader as a later precision upgrade for queue research, after confirming data cost and coverage.

These are integration candidates, not connected accounts or purchased services. Historical market data, historical simulation, and forward paper trading provide different evidence. A paper account processes orders against a simulated current market; it does not rewind the market to evaluate an October 8 historical order.

## Choosing the next integration

For minute-based research, first validate one symbol and a short historical interval with bars, actual trade identifiers, quotes and a documented aggressor-side convention. Start with Alpaca, then compare Massive if necessary. A feed that omits side or pre-execution context may support model inputs while still leaving execution evaluation unmatched. Confirm the chosen plan's historical coverage and paper-data feed before treating it as the affordable option; no current price was verified here.

For seconds and queue behavior, evaluate a venue-specific MBO sample before acquiring a long history. Check additions, modifications, cancellations, executions, order identifiers, sequence resets and exchange priority rules. Databento plus Nautilus is a candidate because their checked source material explicitly supports MBO ingestion. LEAN can also serve as a harness if its custom execution model retains the same evidence requirements. Neither engine makes an inserted order's causal impact observable.

Keep the repository's strict matcher authoritative for economic feedback. A platform's default simulated fill, a paper fill, or an engine-generated queue estimate must not silently replace an observed execution analog. Unsupported intentions remain unmatched; report coverage and sensitivity alongside any conditional portfolio result.

## Information beyond market data

SEC filings, vintage-aware FRED/ALFRED macro data, company investor-relations feeds and permitted news sources are useful additions. Before an adapter becomes part of a historical experiment, preserve release times, revisions, publication times and the earliest actual access time. Period-end fundamentals and today's revised macro history cannot be backdated into a past decision.

Official entry points are [SEC EDGAR APIs](https://www.sec.gov/search-filings/edgar-application-programming-interfaces), [SEC access guidance](https://www.sec.gov/os/accessing-edgar-data), [FRED API documentation](https://fred.stlouisfed.org/docs/api/fred/) and [FRED real-time periods](https://fred.stlouisfed.org/docs/api/fred/realtime_period.html). These primary pages were blocked by this environment's egress proxy, so their current access terms were not verified. No SEC or FRED authenticated integration is implied.

The collection layer accepts configured RSS, HTML or JSON sources. Provider-derived numeric snapshots use `kind="platform"` and a separate feature group. Its canonical fields are `last_price`, `market_cap`, `trailing_pe`, `forward_pe`, `price_to_book`, `dividend_yield`, `analyst_target_price`, `analyst_recommendation`, `short_float_fraction`, `short_interest_ratio`, `implied_volatility`, `borrow_rate`, `borrow_available`, `retail_sentiment` and `discussion_volume`. A provider need not supply every field. Preserve missingness, source units and expiry; do not invent an analyst score or borrow availability from unrelated text.

A provider timestamp describes the source event. A live collection records availability at actual fetch time, with expiry for stale snapshots. The feature builder caps platform freshness at one hour from source publication by default; a new collection cannot renew an old measurement. Platform fields enter the normal trainable feature pipeline, where the model learns their relative importance. Current snapshots do not establish point-in-time historical availability. Any news or social signal also needs provenance, deduplication and resistance to manipulated content.
